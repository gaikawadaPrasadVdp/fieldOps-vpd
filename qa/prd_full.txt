## 4. BUSINESS WORKFLOWS & RULES[cite: 5]

| WORKFLOW | MANDATORY STATES |
| :--- | :--- |
| **Service Request** | NEW → TRIAGED → APPROVED / REJECTED → WORK ORDER CREATED → IN SERVICE → RESOLVED → CONFIRMED → CLOSED[cite: 5] |
| **Work Order** | DRAFT → PLANNED → ASSIGNED → DISPATCHED → IN PROGRESS → ON HOLD → COMPLETED → SUPERVISOR REVIEW → CLOSED[cite: 5] |
| **Preventive Maintenance** | SCHEDULED → DUE → GENERATED → ASSIGNED → COMPLETED → VERIFIED → NEXT CYCLE[cite: 5] |
| **Part Request** | REQUESTED → RESERVED → ISSUED → CONSUMED / RETURNED → RECONCILED[cite: 5] |
| **Asset Status** | ACTIVE → UNDER MAINTENANCE → OUT OF SERVICE → ACTIVE / RETIRED / DISPOSED[cite: 5] |

### 4.1 Critical Business Rules[cite: 5]
* Preventive-maintenance scheduler must generate due work orders without duplicates and correctly handle missed/overdue cycles[cite: 5].
* Work-order state transitions must be server-validated[cite: 5]. Closed work orders must not be silently reopened or edited without controlled authorization/audit[cite: 5].
* Technician assignment must validate technician active status and configured eligibility/conflict rules[cite: 5].
* SLA timers must distinguish response and resolution time and pause only in explicitly configured states[cite: 5].
* Inventory issue, return and transfer must create stock movements under transactional control and remain traceable to work orders where applicable[cite: 5].
* Work-order completion must enforce required checklist, resolution notes and evidence by work type/priority[cite: 5].
* Asset status and downtime history must be derived from controlled events and remain auditable[cite: 5].
* Celery scheduled jobs must process PM generation, overdue reminders, SLA escalation, warranty/AMC expiry and selected report snapshots[cite: 5].

### 4.2 Edge Cases to Handle[cite: 5]
* Maintenance window reschedule without duplicate PM generation[cite: 5].
* Technician reassignment after dispatch or during hold[cite: 5].
* Part reserved but unavailable at issue time[cite: 5].
* Return of unused parts after job completion[cite: 5].
* Multiple incidents against the same asset and duplicate-request detection[cite: 5].
* Asset moved between sites while historical work orders remain linked to original context[cite: 5].
* Warranty/AMC coverage that expires during an open job[cite: 5].
* SLA pause/resume for awaiting-client or approved external dependency states[cite: 5].
